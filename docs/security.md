# 安全与部署边界

## 默认保护

- 管理网页使用仅限同源、HttpOnly、SameSite 会话 Cookie；Android 使用独立作用域的 Bearer 会话，
  两类令牌不能互换。
- Android 不持久化管理密码，只将会话 Token 保存在 Android Keystore 加密存储中；会话不设有效时限，
  仅在服务器修改管理密码后全部失效。
- 登录失败按客户端地址限流；扫描、书架、文件、章节和进度接口均要求有效身份。
- 首次部署可用默认密码 `112233` 初始化，但后台会阻止其他管理操作和 App 登录，直到用户修改密码。
  新密码使用带随机盐的 PBKDF2-SHA256 哈希保存；改密同时轮换会话密钥，使全部旧会话失效。
- CORS 和 API 文档默认关闭；容器以只读根文件系统、禁止提权方式运行，并默认移除全部 Linux
  capabilities。特殊 NAS ACL 确实需要 `DAC_OVERRIDE` 时，只在本地 Compose override 中添加。
- TXT、EPUB、MOBI、XML、进度定位器和请求体均设置尺寸或复杂度上限，文件路径必须留在授权根目录内。
  MOBI 只处理未加密文件，解包任务串行执行，临时文件树受总量、文件数和路径边界检查并在解析后删除。

## 部署要求

1. 部署后立即访问 `/admin#books`，把默认密码 `112233` 修改为唯一的长密码。会话密钥默认自动生成，无需手工配置。
2. 公网访问必须通过 HTTPS 反向代理；App 仅允许局域网地址使用明文 HTTP。
3. 仅把必要的 NAS 目录挂载到容器，数据库和封面目录保持独立可写卷，并定期备份整个 `data/`，其中
   `admin_credentials.json` 是恢复管理访问所必需的凭据文件。
4. 只有存在独立 Web 前端时才配置精确的 `CORS_ORIGINS`，不要使用通配符。
5. 发布 Android App 时使用独立发布密钥；仓库当前的开发签名只用于私有测试与平滑升级。

四位书架密码用于家庭/小团队内的内容隔离，不应视为能抵抗离线暴力破解的高强度加密。管理密码修改后，
既有网页和 App 会话会自动失效，需要重新登录。
